# Secrets Management & Credential Protection (Phase 14)

## 1. Zero Model Secret Exposure

Under no circumstances are secrets, tokens, or credentials injected into the LLM context:
- **Server-Side Credentials**: API keys, database credentials, JWT secrets, and external integration tokens live exclusively in server environment variables and encrypted vaults.
- **Tool Delegation**: When the AI employee decides to invoke a tool (e.g. `lookup_order` or `send_customer_email`), the AI only generates the input arguments (e.g. `order_id`). The server-side tool handler connects using server credentials.
- **Result Sanitization**: Output returned from tools is inspected to ensure credentials, tokens, or private headers are not reflected back to the LLM prompt.

---

## 2. Outbound Leakage Guardrails (`OutputSecurityService`)

The `OutputSecurityService` inspects all outgoing text generated by AI models before transmission:
- **Secret Key Patterns**: Scans for `Bearer eyJ...`, `api_key_...`, `sec_...`, `ghp_...`, AWS access keys (`AKIA...`).
- **System Prompt Leakage**: Detects verbatim echoing of internal prompt rules or security instructions.
- **Violation Action**: If detected, the response is replaced with a safe fallback error message, and a `CRITICAL` `SecurityEvent` (`SECRET_EXPOSURE_ATTEMPT`) is logged.
